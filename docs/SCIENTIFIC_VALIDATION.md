# Scientific numerical validation — 2026-10-23

This records bounded, independent numerical checks across the result-display
plugins. Passing these checks is not a proof for every method, basis, file
variant, or calculation. Tests use synthetic molecules or existing public
fixtures; no private calculation data are included.

## Findings and fixes

Gaussian FCHK rendering cannot represent Cartesian and spherical shells of the
same angular momentum together. Such input now fails explicitly, including
when the optional basis count is missing. It previously could proceed with a
shared shell definition and misleading values.

The Gaussian MO dialog renders alpha orbitals only. For unrestricted input its
title, rows and tooltip now say so, and the wiki no longer claims beta support.
This change does not implement beta rendering.

The ORCA test workflows now install SciPy explicitly so the independent
harmonic comparisons do not silently skip. Native tests also support the old
SciPy harmonic API used by Python 3.9 environments.

## Precision and remaining limits

- ORCA's legacy d(+2) coefficient uses `0.866025` rather than `sqrt(3)/2`.
  The measured maximum relative amplitude error was 4.663e-7 and squared-norm
  error 9.326e-7. The tolerances explicitly allow that approximation.
- ORCA trajectory parsing retains the later nine-decimal `Current Energy`
  summary. It can differ from the twelve-decimal FINAL line by at most about
  5e-10 Eh; the public-fixture check allows 5.1e-10 Eh.
- Stored benzene Cubes were generated by MoleditPy. They are regression
  fixtures, not independent ORCA-exported MO references. The independent MO
  anchors here are analytic functions and SciPy, not real open-shell ORCA Cube
  exports. High-l/ECP and all basis conventions are not comprehensively covered.
- NMR checks validate the implemented first-order spectrum model, not empirical
  chemical-shift/J prediction accuracy or second-order spin effects.
- PySCF is unavailable in this Windows environment. Three real-calculation
  modules skipped and are not counted as validation here. Existing Linux real
  tests compare plugin outputs with direct PySCF energy, Hessian and Cube
  calculations; that checks the plugin boundary, not the correctness of PySCF
  itself against an independent electronic-structure implementation.
- Negative-count Angstrom Cube handling is a legacy compatibility convention,
  not a claim that every Gaussian Cube producer uses that convention. Standard
  Cube output uses atomic units. Some readers retain an older Bohr constant;
  coordinate tolerances allow its approximately 7.2e-8 relative difference.
